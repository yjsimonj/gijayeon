# UI 인식과 클릭 패턴 학습을 결합한 개인화 마우스 보정 시스템 — 실험 설계 및 구현 명세서

> 본 문서는 구현자에게 전달하기 위한 명세서다. 실험 설계의 근거와 함께, 웹 기반 실험 프로그램 및 분석 코드의 요구사항을 정의한다.

---

## 1. 연구 목적과 문제 정의

### 1.1 해결하려는 문제

사용자가 의도한 위치와 실제 클릭 위치 사이에는 항상 오차가 존재하며, 이 오차는 무작위가 아니라 **개인별로 일관된 편향**을 가진다는 가설에서 출발한다. 이 편향을 학습해 클릭 좌표를 사후 보정하면 선택 정확도를 높일 수 있다.

### 1.2 두 접근법의 역할 분담

| 문제 | 담당 | 성격 |
|---|---|---|
| 어떤 버튼을 누르려 했는가 (목표 판별) | UI 인식 (최근접 버튼 스냅) | 기하학적 추정 |
| 그 목표에서 얼마나 어긋나게 찍는가 (오차 예측) | 궤적 기반 회귀 모델 | 지도학습 |

두 방식은 경쟁 관계가 아니라 **보완 관계**이며, 본 연구의 핵심 가설은 두 방식의 결합이 각각의 단독 적용보다 우수하다는 것이다.

### 1.3 학습/추론의 비대칭 (중요)

```
학습 시:  버튼 중심 좌표 필요 (정답 라벨 생성용)
추론 시:  버튼 정보 불필요 (궤적만으로 보정량 산출)
```

추론 시점에 버튼 중심을 알아야 한다면 "이미 아는데 왜 보정하나, 그냥 그 버튼을 누르면 되지 않나"라는 비판이 성립한다. 따라서 모델은 **궤적 특징만을 입력으로 받고 보정 벡터를 출력**해야 한다.

```
학습:  (궤적 특징) → (버튼중심 − 클릭좌표)
추론:  보정좌표 = 클릭좌표 + 모델(궤적 특징)
평가:  보정 전/후의 |좌표 − 버튼중심| 및 성공 여부 비교
```

## 2. 오차의 정의

### 2.1 좌표계 회전

화면 x, y 축 그대로 사용하면 방향이 다른 시행끼리 오차가 상쇄되어 신호가 소실된다. **커서 진행 방향을 기준으로 분해**한다.

- `e∥` (진행 방향 성분): 오버슛/언더슛 → 이동 속도와 연관
- `e⊥` (수직 성분): 횡방향 치우침 → 손·손목 구조에서 오는 개인 편향

두 성분은 발생 원인과 예측 변수가 다르므로 반드시 분리한다.

### 2.2 진행 방향의 정의

**진행 방향 θ는 클릭 직전 80ms 구간의 변위 벡터로 정의한다.**

```
u = (P_click − P_(click−80ms)) / |P_click − P_(click−80ms)|
```

여기서 `P_(click−80ms)`는 클릭 시각으로부터 80ms 이상 이전인 궤적 샘플 중 가장 최근의 것이다.

**다른 정의를 쓰면 안 되는 이유**

| 잘못된 정의 | 문제 |
|---|---|
| 시작점 → 클릭점 직선 | 사람은 직선으로 움직이지 않는다. 곡선 궤적에서 실제 접근 방향과 크게 어긋난다 |
| 마지막 한 샘플 (약 16ms) | 감속 구간이라 변위가 1~2px에 불과해 방향이 노이즈로 튄다 |

**예외 처리**: 80ms 구간의 변위가 3px 미만이면 방향 추정이 불안정하다. 해당 시행에 플래그를 남기고 구간을 150ms로 확대해 재계산한다. 재계산에서도 3px 미만이면 방향 의존 특징을 결측 처리한다.

### 2.3 오차 성분 계산 절차

```
1. 오차 벡터        E = (클릭x − 중심x, 클릭y − 중심y)
2. 진행 방향 단위벡터 u = (cos θ, sin θ)          ← 2.2절 정의
3. 수직 단위벡터     u⊥ = (−sin θ, cos θ)
4. 투영             e∥ = E · u
                    e⊥ = E · u⊥
5. 정규화           e∥_norm = e∥ / r,  e⊥_norm = e⊥ / r   (r = 버튼 크기 / 2)
```

**부호 규약**

| | 양수 | 음수 |
|---|---|---|
| `e∥` | 오버슛 (목표를 지나침) | 언더슛 (덜 감) |
| `e⊥` | 진행 방향 기준 한쪽 치우침 | 반대쪽 치우침 |

화면 좌표계의 y축이 아래로 증가하므로 `e⊥`의 좌우 대응은 수학적 직관과 반대다. **구현 시 부호 방향을 주석에 명시하고, 분석 전 시각화로 한 번 검증할 것.** 여기서 실수하면 개인 편향의 방향이 반대로 보고된다.

**보정 시 역변환**

```
E_pred = r * (e∥_pred * u + e⊥_pred * u⊥)
보정좌표 = 클릭좌표 − E_pred
```

`E`를 "클릭 − 중심"으로 정의했으므로 예측값을 **빼야** 중심 방향으로 이동한다.

### 2.4 버튼 크기 정규화

```
e_norm = (클릭좌표 − 버튼중심) / 버튼 반폭
```

버튼 내부가 −1 ~ 1 구간이 되고, 절댓값이 1을 초과하면 실패다. 크기가 다른 조건의 데이터를 함께 학습·분석하려면 필수다.

### 2.5 평가는 성공 여부로

목적함수를 "중심에 가깝게"로 두면 잘못된 목표를 최적화하게 된다. 버튼은 면적을 가지므로 중심을 맞출 필요가 없다. 실제 목표는 **버튼 내부에 들어갈 확률의 최대화**다.

| 지표 | 정의 | 역할 |
|---|---|---|
| 성공률 | 목표 버튼 내부 클릭 비율 | 주 지표 |
| 오선택률 | 목표가 아닌 버튼을 누른 비율 | 주 지표 (스냅 방식의 위험 측정) |
| 미스율 | 어느 버튼에도 들어가지 않은 비율 | 보조 |
| 오차 거리 | `√[(Δx)² + (Δy)²]` (px) | 보조 지표, 검정력 확보용 |
| 여유(margin) | 가장 가까운 경계까지 거리 | 성공률이 천장일 때 개선 확인용 |

`성공률 + 미스율 + 오선택률 = 100%`

**오차 거리는 스냅 방식에 적용하지 않는다.** 스냅은 맞으면 0, 틀리면 이웃 버튼까지 거리이므로 성공/실패를 거리로 다시 쓴 것에 불과하다. 스냅은 성공률·오선택률로만 평가한다.

## 3. 실험 설계

### 3.1 전체 구조

| 단계 | 내용 | 시행 수 |
|---|---|---|
| 0 | 예비 실험 (조건 캘리브레이션) | 90 |
| 1 | 학습 데이터 수집 (단일 버튼) | 400 |
| 2 | 단일 버튼 평가 | 120 |
| 3 | 다중 버튼 평가 | 240 |

본 실험 총 760회, 휴식 포함 약 50분. 참가자 최소 8명, 권장 12명 이상.

### 3.2 0단계 — 예비 실험

본 실험 조건을 자의적으로 정하지 않기 위한 사전 측정. 참가자 2~3명, 각 90회.

- 버튼 크기 6 / 10 / 16 / 24 / 32px를 각 18회씩 제시
- **성공률 75~90% 구간에 드는 크기 3종을 본 실험용으로 채택**
  - 100%면 천장 효과로 비교 불가, 50% 이하면 과제 자체가 무의미
- 동시에 **개인 오차 표준편차 σ 측정** → 3단계 간격 설정에 사용

### 3.3 1단계 — 학습 데이터 수집 (단일 버튼 400회)

| 항목 | 설정 |
|---|---|
| 버튼 크기 | 0단계에서 정한 3종, **매 시행 무작위** |
| 이동 거리 | 300 / 600px 무작위 |
| 방향 | 8방향 균등 배분 후 순서 무작위 |
| 시간 제한 | 목표 등장 후 1ms (초과 시 timeout 플래그만, 시행은 안 끝남 — 3000ms까지 무응답이면 click:null로 강제 종료. sudo 지시로 500→1 변경) |
| 시행 절차 | 화면 중앙 홈 버튼 클릭 → 목표 버튼 등장 → 클릭 |
| 휴식 | 50회마다 30초 강제 (스킵 불가) |

**설계 근거**

- *크기를 블록으로 묶지 않는 이유*: "10px 100회 → 20px 100회 → 30px 100회" 순서면 크기 효과와 피로·연습 효과가 완전히 교락되어 분리 불가능하다.
- *홈 버튼을 두는 이유*: 없으면 이전 클릭 위치가 다음 시행의 시작점이 되어 이동 거리·방향 통제가 무너진다.
- *시간 제한을 두는 이유*: 없으면 사용자가 버튼 위에서 미세 조정을 해버려 오차가 거의 발생하지 않는다. 학습할 패턴 자체가 생기지 않는다.
- *8방향 균등 배분*: 방향에 따라 개인 편향이 다르므로 한쪽에 몰리면 모델이 편향된다.

### 3.4 2단계 — 단일 버튼 평가 (120회)

1단계와 동일 조건으로 **새로 수집**한다. 학습에 사용한 데이터로 평가해서는 안 된다.

- **비교**: 보정 없음 vs AI 보정
- **지표**: 성공률, 평균 오차 거리, 정규화 오차, 여유
- 스냅은 이 단계에 포함하지 않는다 (버튼이 하나이므로 정의상 100%)

이 단계의 역할은 **개인 편향이 실제로 학습 가능한지 검증**하는 것이다.

### 3.5 3단계 — 다중 버튼 평가 (240회)

- 3×3 격자 배치, 목표 버튼만 색상으로 표시
- 크기 3종 × 간격 3종 = 9칸, 칸당 약 27회
- **크기와 간격 모두 매 시행 무작위**

**간격은 개인 σ 기준으로 설정** (절대 픽셀로 정하면 참가자마다 난이도가 달라진다)

| 수준 | 간격 | 예상 결과 |
|---|---|---|
| 밀집 | 0px (맞붙음) | 스냅이 확실히 깨짐. 툴바·캘린더 셀 등 실제 UI에 흔한 배치 |
| 중간 | 1σ | 방식 간 역전이 일어날 경계 구간 |
| 분리 | 3σ | 스냅 거의 100%. AI 단독으로는 이길 수 없음 |

3σ 조건은 AI가 불리한 조건이지만 **의도적으로 포함한다.** 간격에 따라 유불리가 뒤집히는 그래프가 이 연구의 핵심 결과이며, 지는 조건을 보고하는 것이 신뢰도를 높인다.

**비교 4조건** — 참가자는 한 번만 클릭하고, 동일한 로그에 계산만 네 번 적용한다.

| 조건 | 판정 좌표 |
|---|---|
| A. 보정 없음 | 원본 좌표 |
| B. AI 보정 | 원본 + 예측 보정량 |
| C. 스냅 | 원본 기준 최근접 버튼 |
| D. 결합 | 보정 좌표 기준 최근접 버튼 |

**오프라인 재평가의 이점**: 네 조건이 완전히 동일한 클릭을 사용하므로 피로·연습 효과·컨디션이 모든 조건에 동일하게 작용한다. 참가자에게 조건별로 반복 시행시키는 설계에서 발생하는 순서 효과가 원천적으로 제거된다.

**D 조건의 존재 이유**: 연구 제목이 "UI 인식**과** 클릭 패턴 학습을 **결합**"이므로, 두 방식을 경쟁시키기만 하면 제목의 주장이 검증되지 않는다. D가 C의 오선택률을 낮추면 결합의 효과가 실증된다.

## 4. 모델 명세

### 4.1 구조

```
입력 (6차원: 접근 각도가 sin·cos 2개로 분해됨)
  - 접근 각도        : 클릭 직전 80ms 변위 벡터의 방향 θ (2.2절 정의와 동일)
                       → sin θ, cos θ 두 값으로 분해해 입력할 것
                         (각도를 그대로 넣으면 359°와 1°가 먼 값으로 취급됨)
  - 최고 속도        : 궤적 중 최대 순간 속도 (px/ms)
  - 감속 시작 시점   : 속도가 최대치의 50%로 떨어진 시점 (클릭 기준 역산 ms)
  - 이동 거리        : 시작점~클릭점 직선 거리
  - 버튼 반폭        : 목표 버튼 크기의 절반

출력 (2개)
  - e∥, e⊥  (버튼 반폭으로 정규화된 값)

모델: 릿지 회귀 (Ridge Regression)
검증: 5-fold 교차검증 (무작위 분할)
```

### 4.2 모델 선택 근거

데이터가 참가자당 400개 수준이므로 LSTM 등 시계열 딥러닝을 적용하면 과적합이 확실하다. 릿지 회귀는 계수 해석이 가능해 **"이 참가자는 접근 속도가 빠를 때 진행 방향으로 오버슛한다"**와 같은 설명 가능한 결과를 제공한다는 부수적 이점도 있다.

### 4.3 데이터 전처리

- 앞 20회는 워밍업으로 분석에서 제외
- 시간 초과 시행은 별도 플래그를 남기되 제외하지 않음 (속도-정확도 교환의 일부)

### 4.4 교차검증 방식

**주 분석은 k-fold 무작위 분할**을 사용한다. 시간순 분할(앞 200 학습 / 뒤 200 평가)은 평가셋에만 피로가 집중되어 모델이 부당하게 불리해진다. 다만 시간순 분할 결과를 **실사용 시나리오로 보조 보고**하면 주장이 강화된다.

### 4.5 보정 적용 게이팅

예측 오차의 크기가 버튼 반폭 대비 0.5 이하이면 보정을 적용하지 않는다. 이미 안전하게 들어간 클릭을 건드릴 이유가 없고, 모델이 틀렸을 때의 피해를 줄인다.

## 5. 구현 요구사항

### 5.1 기술 스택

- **실험 프로그램**: HTML + JavaScript (브라우저 단독 실행)
- **분석**: Python (pandas, scikit-learn, scipy, matplotlib)
- **데이터 교환**: JSON 또는 CSV 내보내기

### 5.2 실험 웹페이지 요구사항

**공통**

- 전체 화면(fullscreen) 모드 강제, 브라우저 UI에 의한 좌표 오차 방지
- 화면 해상도와 devicePixelRatio 기록
- 마우스 이동 이벤트를 최소 60Hz로 샘플링 (`mousemove` + `requestAnimationFrame`)
- 클릭 직전 **200ms 구간의 궤적을 반드시 확보** (샘플이 부족하면 해당 시행 플래그)
- 우클릭·드래그·키보드 입력 무시
- 진행률 표시 및 휴식 타이머 UI

**시행 흐름**

```
1. 화면 중앙에 홈 버튼 표시
2. 홈 버튼 클릭 → 궤적 기록 시작
3. 무작위 방향·거리에 목표 버튼 등장 (등장 시각 기록)
4. 사용자 클릭 → 좌표·시각 기록, 궤적 기록 종료
5. 1ms 초과 시 timeout 플래그(시행은 안 끝남, 클릭 계속 받음), 3000ms까지도 무응답이면 click:null로 강제 종료
6. 200ms 공백 후 다음 시행
```

**단계별 차이**

- 1·2단계: 목표 버튼 1개만 표시
- 3단계: 3×3 격자 9개 버튼 표시, 목표만 색상 구분. 격자 중심이 지정 거리·방향에 오도록 배치

### 5.4 분석 스크립트 요구사항

1. **특징 추출**: 궤적 → 특징 벡터 (진행 방향은 2.2절 정의 준수)
2. **오차 계산**: 진행 방향 기준 회전 → e∥, e⊥ → 버튼 반폭 정규화
3. **모델 학습**: 릿지 회귀 + 5-fold CV, 참가자별 개별 모델
4. **오프라인 재평가**: 3단계 로그에 A/B/C/D 4조건 판정 적용
5. **통계 검정** (아래 표)
6. **시각화**: 간격별 조건 비교 그래프, 오차 산점도, 개인별 편향 벡터

## 6. 통계 분석 계획

| 비교 | 검정 방법 |
|---|---|
| 성공률 (같은 시행의 이진 결과) | McNemar 검정 |
| 오차 거리 (같은 시행의 연속값) | 대응표본 t-검정 (정규성 위반 시 Wilcoxon) |
| 4조건 동시 비교 | Cochran's Q → 사후 McNemar + Bonferroni 보정 |
| 참가자별 평균 비교 | 대응표본 t-검정 (n = 참가자 수) |
| 피로 효과 확인 | `오차 ~ 조건 + 시행번호` 회귀, 시행번호 계수 보고 |

**보고 방식**: 효과크기(Cohen's d)와 절대 수치를 반드시 병기한다. "p < 0.05"보다 "평균 오차 8.3px → 5.1px, 38% 감소"가 훨씬 명확하다.

**피로 효과는 제거 대상이 아니라 측정 대상이다.** 시행번호를 공변량으로 넣어 회귀하면 "760회 구간에서 유의한 정확도 저하는 관찰되지 않았다" 또는 "시행당 0.01px씩 증가했다"는 결과가 나오며, 이 자체가 보고 가치가 있다.

## 7. 예상 결과와 대비

### 7.1 주요 가설

- **2단계**: AI 보정이 오차 거리를 유의하게 감소시킨다 → 개인 편향의 학습 가능성 입증
- **3단계**: 간격 0px에서 C(스냅)의 오선택률이 급증하고, D(결합)가 이를 완화한다

```
오선택률
  ↑
  │ C(스냅) ╲
  │          ╲___
  │ D(결합) ╲___
  │              ‾‾‾
  └─────────────────→ 간격
    0     1σ     3σ
```

**C와 D의 격차가 사라지는 지점**이 "이 간격 이상이면 궤적 정보가 불필요하다"는 실용적 UI 설계 기준이 되며, 이것이 본 연구의 최종 결론이다.

### 7.2 스냅 방식의 구조적 약점

스냅은 연속적 위치 보정이 아니라 **이산적 목표 재배정**이다. 따라서 중간이 없고, 미스를 전부 오선택으로 전환한다. 원래 "아무 일도 일어나지 않았을" 클릭이 "엉뚱한 버튼 실행"이 되므로 실사용 관점에서는 오히려 위험하다. 이 점이 오선택률을 주 지표로 삼는 이유다.

### 7.3 결과가 기대와 다를 경우

성공률 개선이 나오지 않더라도 다음을 반드시 보고한다.

- 궤적 특징의 설명력 (R²)
- 개인별 편향의 일관성 (참가자 내 vs 참가자 간 분산 비교)
- 상수 보정(개인 평균 오차만 차감) 대비 조건부 회귀의 이득

**베이스라인을 3단계로 두는 것이 핵심이다.**

1. 보정 없음
2. **개인 평균 오차만 차감하는 상수 보정**
3. 궤적 조건부 회귀

②만으로 대부분이 설명되더라도 "개인 편향은 상황 의존적이라기보다 고정 오프셋에 가깝다"는 유효한 결론이 된다. 실패가 아니라 발견이 되도록 설계해 둔 것이다.
